# Design

## Context

Формы создания и редактирования используют общий `ContactForm` и серверную схему `contactInputSchema`. Действия `createContact` и `updateContact` сохраняют контакт в транзакции вместе с группами. Карточка читает все поля контакта через `getContact(userId, id)`.

Главная в `src/app/(app)/page.tsx` получает владельца из сессии. Для списка «Пора связаться» запрос и сортировка уже выполняются в PostgreSQL, а серверная страница скрывает блок при поиске и выборе действительной группы.

## Goals / Non-Goals

Использовать существующие пути чтения и сохранения контактов, изоляцию по владельцу и московский календарь. Вычислять ближайший день рождения при загрузке главной и после переходов, которые обновляют её данные.

## Decisions

- **Хранение.** Добавить в `contacts` столбец `birth_date` типа PostgreSQL `date` с допустимым `NULL`. В Drizzle использовать представление `YYYY-MM-DD` строкой. Это сохраняет календарный день при передаче между формой, базой и карточкой. Для существующих контактов `NULL` естественно означает пустое поле.
- **Сохранение.** Использовать `input type="date"` в общем диалоге. Серверная схема проверяет строку как календарную дату и сравнивает её с текущим московским днём из `toMoscowInput`. Пустая строка превращается в `null`. Передавать результат через существующие действия и транзакции. Проверить обновление главной через `/?added=…` после создания и через действующую инвалидацию после правки и удаления.
- **Выборка.** Добавить запрос по `userId` в `src/db/queries.ts`. Взять семь дней от существующего выражения `moscowDay(now())`. Для каждого дня сопоставить дату рождения, сдвинутую на разницу календарных лет, с этим днём. Прибавление календарных лет к исходной дате использует правило PostgreSQL о последнем дне месяца, поэтому 29 февраля превращается в 28 февраля только в невисокосном году. Окно может содержать даты двух лет. Для тестов запрос может принимать момент проверки, по умолчанию использовать `now()` базы. Проекция содержит идентификатор, имя и дату ближайшего дня рождения. Сортировка использует дату и готовый `alphabeticalOrder` с русской сортировкой имени и `id` для тёзок.
- **Отображение.** На главной поставить блок над списком рядом с «Пора связаться». Использовать ту же проверку непустого поиска и выбранной группы до запроса. Сделать строки ссылками на `/contacts/[id]`. В карточке подставить дату в существующий компонент `Detail`. Для обоих форматов переиспользовать календарное форматирование из `src/lib/format.ts` с UTC при выводе строковых дат. В карточке нужен год рождения, в блоке нужны день и месяц ближайшего дня рождения.

## Risks / Trade-offs

- Смена суток в Москве может расходиться со сменой даты у сервера и браузера. Использовать заданный `appTimeZone` в расчёте окна и проверке будущей даты. Проверить границу суток фиксированным моментом.
- Добавление поля меняет типы формы и сохранения. Обновить явные объекты формы и тестовые данные, чтобы прежние сценарии создания и редактирования продолжали проходить с пустой датой.

## Migration Plan

Сгенерировать миграцию `pnpm db:generate`, проверить, что она добавляет только nullable-столбец, и применить её обычным `pnpm db:migrate` перед запуском новой версии. При откате приложения оставить столбец в базе, чтобы сохранить уже введённые даты.

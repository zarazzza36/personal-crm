# Proposal

## Why

Приложением хотят пользоваться друзья, а сейчас все, кто открывает адрес, видят одни и те же контакты. Нужно, чтобы каждый входил под своей почтой и вёл свои контакты, а чужие не видел. Исходная спека — `specs/02-пользователи-вход.md`.

## What Changes

- **BREAKING** Без входа приложение не открывается: любая страница ведёт на страницу входа. Открыты без входа только страница входа, `/health` и картинка для превью ссылок
- Страница входа: поле «Почта» и кнопка «Получить ссылку». После отправки — «Ссылка для входа отправлена на <почта>»; ответ не выдаёт, есть ли уже такой пользователь. Паролей нет, первый вход и есть регистрация, имя не спрашиваем
- Почта: пробелы по краям убираются, регистр букв не важен. Неверный адрес — «Проверьте адрес почты», письмо не уходит. Сервер проверяет так же, даже если запрос пришёл не из формы
- Ссылка из письма работает один раз и 15 минут. Новая ссылка отменяет старые. Устаревшая или уже использованная — страница «Ссылка устарела, запросите новую» с кнопкой на страницу входа
- Не больше 3 писем на одну почту за 10 минут, дальше — «Слишком часто, попробуйте через несколько минут»
- Вход держится 30 дней с последнего захода на этом устройстве; можно быть в приложении с нескольких устройств сразу
- В шапке вместо надписи «ДЛЯ ЛОГИСТОВ» — почта пользователя и кнопка «Выйти». Выход — только на этом устройстве. На странице входа шапка прежняя
- Письмо: отправитель «Личная CRM» `noreply@mail.crm.volki-lzkv.ru`, тема «Вход в Личную CRM», кнопка «Войти», «Ссылка работает 15 минут», «Если вы не запрашивали вход — просто проигнорируйте письмо»
- Куда уходят письма, решают настройки, код один: на компьютере и в автотестах — в почтовую заглушку Mailpit, на сервере — настоящие письма через Resend. Отправляет везде Nodemailer
- **BREAKING** У каждого контакта и каждой группы — владелец, заметки принадлежат владельцу контакта. Пользователь видит и меняет только своё: список, поиск, карточку, заметки, напоминания, группы, фильтр, «Пора связаться». Чужая запись не открывается ни в интерфейсе, ни прямым запросом к серверу; чужой контакт по ссылке — «Контакт не найден», как несуществующий
- Группы у каждого свои: у двух пользователей может быть по группе «Друзья». Запрет одинаковых названий — только внутри групп одного пользователя
- Новый пользователь видит пустой список и подсказку «Добавьте первый контакт»
- Все контакты, заметки и группы, которые уже есть в базе, становятся данными пользователя с почтой владельца. Почта владельца — настройка `OWNER_EMAIL` в `.env` (на компьютере и на сервере), в репозиторий она не попадает: он публичный. Ни одна запись не теряется. Тестовые данные `pnpm db:seed` создаются у этого же пользователя
- Все тексты входа — на «вы», как остальной интерфейс
- Автотесты: e2e-тест критерия успеха (A добавил контакт, B его не видит ни в списке, ни в поиске, ни по ссылке) и e2e-тесты входа берут ссылку из Mailpit. Тест главного сценария из `specs/01-продуктовая-идея.md` остаётся отдельным и перед сценарием входит под пользователем
- Откат после этой выкатки — только вместе: прошлая версия приложения и база из бэкапа, снятого перед выкаткой. README — как это сделать

## Capabilities

### New Capabilities

- `user-auth`: вход по ссылке из письма — страница входа, проверка почты, срок и одноразовость ссылки, лимит писем, письмо и куда оно уходит, длительность входа, выход, закрытые без входа страницы
- `data-ownership`: чьи данные — владелец у контактов и групп, видимость и изменение только своего везде, «Контакт не найден» для чужого, пустой список нового пользователя, передача существующих данных владельцу

### Modified Capabilities

- `contact-groups`: требование «Создание группы» — одинаковых названий без учёта регистра нет только внутри групп одного пользователя, сначала групп нет у каждого нового пользователя

## Impact

- База: новые таблицы Better Auth — пользователи, сессии, аккаунты, проверочные токены — и таблица отправленных писем для лимита. В `contacts` и `groups` — обязательное поле владельца; уникальность названия группы — внутри одного пользователя. Миграция **меняет существующие данные**: создаёт пользователя-владельца и проставляет его всем контактам и группам. Её покажу до merge
- Код: каждый запрос к базе и каждый server action получает пользователя из сессии и работает только с его записями. Новые страницы: вход и «Ссылка устарела». Проверка входа на каждой странице. Шапка, текст пустого списка, страница «Контакт не найден»
- Новые библиотеки, названные в спеке: `better-auth` 1.7.24 и `nodemailer` 10.5.0 (+ `@types/nodemailer` 8.0.2 для разработки). Mailpit `axllent/mailpit:v1.33.1` — в `docker-compose.yml` локально и сервисом в CI
- Настройки: `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `SMTP_URL`, `OWNER_EMAIL` — в `.env` на компьютере и на сервере, в `.env.example` без значений; `deploy/app/compose.yaml` передаёт их приложению и разовому контейнеру миграций
- CI: Mailpit и тестовые значения настроек для Vitest и Playwright
- Только человек: аккаунт в Resend, проверка домена `mail.crm.volki-lzkv.ru` — записи DNS у регистратора, ключ Resend и строки в `.env` на сервере до выкатки. Без них выкатка остановится до миграций, прод продолжит работать на прежней версии
- Все существующие e2e- и Vitest-тесты переходят на работу от имени пользователя
